# 三 Agent 共享分支协作协议

## 1. 权限模型

三个 Agent 共用当前分支和工作区，职责通过角色文件隔离：

| 角色 | 可以做 | 不可以做 |
| --- | --- | --- |
| 产品经理 | 改产品文档、任务板、验收记录；审核全部结果；提交和推送 | 未审核直接要求上线；强制覆盖改动 |
| 策划专家 | 改设计文档、资源规格、数值表、关卡规则 | 直接改核心 C#；直接推送 |
| 开发专家 | 改代码、场景、Prefab、配置和实现所需资源；补测试 | 改产品方向；绕过设计扩大范围；直接推送 |

“不可以”表示默认禁止；若确实需要越权，必须在任务板记录原因并由产品经理确认。

## 2. 单分支工作顺序

共享分支不是多人同时无序写入，而是按任务锁顺序工作：

1. 产品经理在 `Plan/AGENT_TASK_BOARD.md` 登记任务，指定当前负责 Agent。
2. 当前 Agent 将任务状态改为 `进行中`，读取相关设计和现有实现。
3. 当前 Agent 只修改任务范围内文件，完成后写交接报告。
4. 产品经理检查 Git diff、测试证据和验收标准。
5. 通过后产品经理提交并推送；不通过则建立返工任务。

同一时间只允许一个 Agent 修改共享工作区。另一个 Agent 需要工作时，先等待任务状态变为 `可接手`。

## 3. 任务状态

`待拆分 -> 待策划 -> 待开发 -> 开发中 -> 待验收 -> 返工 -> 已完成`

阻塞任务使用 `阻塞`，必须记录阻塞原因、需要谁决策以及下一步。

## 4. 交接要求

交接必须使用 `Plan/AGENT_HANDOFF_TEMPLATE.md`，至少包含：

- 任务编号和目标
- 修改文件
- 设计或产品依据
- 测试命令和结果
- Unity 手工验证步骤
- 已知风险和待确认问题

没有交接报告的代码或资源只能视为未交付。

## 5. 产品经理提交门禁

产品经理执行提交前必须确认：

- 任务板状态为 `待验收` 或 `已完成`。
- 设计文档和实现结果一致。
- Runtime、Editor 和相关测试构建通过。
- Unity Console 没有新增编译错误、空引用或资源导入错误。
- 未提交改动都能解释，未包含临时文件、Library、缓存或无关格式化。
- 每日记录和测试记录已更新。

只有通过以上门禁，产品经理才执行 `git commit` 和 `git push origin 茶杯头复刻`。

## 6. 冲突处理

- 不使用 `git reset --hard`、`git checkout --` 或强制推送来解决冲突。
- 先保存当前 Agent 的报告，再由产品经理判断保留、合并或撤销哪一部分。
- 场景、Prefab 和资源冲突优先人工比较 YAML 和 GUID，不直接覆盖。
- 代码冲突按产品目标、策划规则、现有架构顺序决策。
