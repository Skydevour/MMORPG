# Spine Optimizer

用于将 Spine 的应用规范与性能优化经验，整理为可执行的优化清单、排查路径和落地方案。

## 何时调用

- 用户要求“优化 Spine 性能”“总结 Spine 优化方案”“做 Spine 性能排查”时
- 需要在 CPU/GPU/内存/包体之间做 Spine 取舍时
- 需要把零散经验沉淀为统一规范、评审标准、发布前检查表时

## 输出目标

- 输出结构化结论：问题 -> 原因 -> 优先级 -> 方案 -> 风险 -> 验证方式
- 优先提供可落地动作，避免泛泛建议
- 明确区分“开发期建议”和“正式包建议”

## 核心知识库

### 1. 资源基础与应用边界

- Spine 资源通常包含：`png(atlas图片)`、`atlas`、`skel/json`
- 核心对象：Bones、Slots、Attachments、Animations、Skins、Events
- 选型建议：
- 复杂角色动作、IK、换装、动画混合 -> 优先 Spine
- 简单位移缩放透明、UI 小动效 -> 优先动效编辑器/节点动画
- 骨骼难复现且逐帧差异大特效 -> 优先序列帧

### 2. 常用能力与注意点

- 动画融合：通过 `DefaultMix` 控制切换平滑度
- 多轨道：`Track0(基础循环)`、`Track1(局部动作)`、`Track2(表情等叠加)`
- 骨骼跟随：用于挂点特效/UI/命中检测同步
- 换装两方案：
- 皮肤切换：部件集合固定、复用高
- 动态换图：部件种类多、运行时按需替换
- 自定义 Shader：
- `CustomSlotMaterials` 可做局部闪白/描边
- 额外材质通常增加 DrawCall
- 运行时改材质避免共享实例串状态
- Skeleton Debug：用于校验骨骼、插槽附件、渲染顺序、事件与统计量

### 3. Alpha 流程规范（高频坑位）

- Spine 默认 `Spine/Skeleton` 多配合预乘 Alpha（PMA）渲染
- 若输入是 Straight Alpha，需在 shader 中启用“乘以 alpha”的补偿逻辑（如 `_STRAIGHT_ALPHA_INPUT`）
- 已预乘图片再走 Straight Alpha 补偿会导致半透明区域发暗（二次预乘）
- 无特殊需求，实时渲染推荐 PMA；需要图像二次编辑再考虑 Straight Alpha

### 4. 资源层优化

- `skel(binary)` 相比 `json`：通常 GC 更低、解析更快、体积更小
- 建议：开发调试可用 JSON；正式包优先 binary
- 计算开销优先级通常为：
- 骨骼数量 > 顶点数量 > 关键帧曲线复杂度
- 无法合批常见原因：
- 顶点超平台/实现限制（示例里提到 300）
- 混合模式不一致（Additive/Multiply 等）
- 多图集与材质不一致
- 图集建议：
- 尺寸不超过 `2048`
- 宽高尽量可被 `4` 整除
- 导出时保证 PMA 策略一致
- 原图先 Trim 再打图，减少无效留白、内存与包体浪费

### 5. 运行时优化

- 对象池：减少频繁创建/销毁 Spine 实例
- 逐帧分摊创建：避免单帧集中实例化导致卡顿
- 隔帧刷新（`updateInterval`）：
- 高端：`0`（全帧）
- 中端：`1~2`
- 低端：`2~4`
- 可视优先级策略：
- 主角/UI 保持全帧
- 背景角色/屏外对象降频

### 6. 大规模场景高级方案

- 挂点小人（静态帧数据+拼接）：
- 预解析并缓存每帧骨骼结果，运行时只读缓存，显著降 CPU
- 局限：不支持 Mesh 类复杂附件
- 多图集 Spine 合批：
- 可将图集索引编码进顶点色通道，在 shader 中按索引采样多纹理
- 关键前提：控制顶点数不过阈值，屏蔽不可见附件顶点
- 跨类型合批（Spine + 建筑网格）：
- 共享材质与渲染路径可减少 DrawCall
- 受限于移动端可用纹理采样数量（常见上限约 8）

## 标准输出模板

当用户请求“帮我优化 Spine”时，按以下结构输出：

1. 场景画像：角色数量、同屏峰值、平台、帧率目标、是否多图集
2. 瓶颈定位：CPU(动画更新/骨骼求值) / GPU(DrawCall/带宽) / 内存(纹理/缓存)
3. 快速收益项（1-2 天可落地）
4. 中期改造项（1-2 周）
5. 高阶方案（需要引擎/渲染改造）
6. 风险与回滚策略
7. 验证指标：FPS、DrawCall、主线程耗时、内存峰值、加载耗时

## 执行准则

- 优先做“低风险高收益”：对象池、降频更新、图集规范、binary 导出
- 再做“中风险中收益”：换装架构收敛、骨骼/顶点减负
- 最后做“高收益高复杂”：多图集合批、跨类型合批、离线帧缓存方案
- 所有优化必须提供“优化前/后”对比数据，不接受无指标结论

## 代码实现规范

### A. 运行时创建与回收

- 统一走 Spine 对象池：`Get -> Init -> Play -> Recycle`
- 禁止高频业务路径中 `new SkeletonAnimation` 与 `DestroyImmediate`
- 同类 Spine 实例采用“分帧创建”策略，限制单帧创建上限

### B. 更新频率与优先级

- 每个 Spine 维护 `updateInterval` 与 `priority`
- 主角/UI：`updateInterval=0`
- 中低优先级与屏外对象：按设备档位动态升高 `updateInterval`
- 更新调度需稳定分布，避免同帧扎堆执行

### C. 渲染与材质规则

- 同批次 Spine 必须统一：材质、混合模式、纹理采样路径
- 局部特效（闪白/描边）优先复用材质参数，不随意新增材质实例
- 使用 `CustomSlotMaterials` 时记录额外 DrawCall 成本并做开关兜底

### D. 换装实现边界

- 固定部件组合优先 `Skin` 合并切换
- 高迭代/动态资源优先“运行时附件替换”
- 换装后统一执行“回到 setup pose + 刷新可见插槽”流程，避免残留姿态

### E. 资源导出与版本约束

- 正式包强制 binary（`skel`），JSON 仅用于开发调试
- 图集约束：尺寸不超 `2048`、可被 `4` 整除、导出策略与 PMA 一致
- 原图必须 Trim 后入库，避免无效透明区域放大包体和显存

### F. 验证与回归标准

- 每次优化至少产出一组对比：`FPS`、`DrawCall`、主线程耗时、内存峰值
- 提交时附“可回滚开关”与“影响范围说明”
- 未通过同屏峰值压测的优化禁止默认全量开启

## 快速检查清单

- 是否统一了材质、混合模式、图集策略？
- 是否存在不必要骨骼、顶点、关键帧？
- 是否已对屏外或低优先角色降频？
- 是否正式包使用 binary 而非 JSON？
- 是否验证过 PMA/Straight Alpha 配置一致？
- 是否建立了同屏峰值压测场景并记录指标？
