# PM-008：构图、动作与 UI 体验返工审核

日期：2026-09-14。主 Agent：产品经理米浴。协作：策划与开发分别只读审核 UI、角色动画链路；产品统一成文。本轮不修改运行时代码，不提交推送。

## 产品结论

当前版本是三形态功能验证版，体验验收不通过。用户提出的镜头远、Boss 缺乏压迫感、跳跃翻身不连贯、UI 生硬，均应进入本轮返工。DEV-008 的 36/36 测试结果仍是有效工程证据，但不能证明构图、动画或 UI 达到成品标准。

下一版唯一主目标：让玩家在同一屏内清楚感到 Boss 的体量、自己的即时操控和每一次战斗结果。先完成土豆阶段的体验标杆，再把同一规则覆盖到洋葱和胡萝卜。

## 构图方案比较

| 方案 | 收益 | 代价 | 决策 |
| --- | --- | --- | --- |
| 仅拉近相机 | 主角和弹体同步变清楚 | 原站位可能出屏，留给跳跃与预警的空间变小 | 不单独采用 |
| 仅放大 Boss | 提升体量对比、操作视野保持 | 主角依旧偏小，透明框/碰撞体会挤压舞台 | 不单独采用 |
| 适度拉近＋单独放大 Boss＋站位内收 | 同时改善主体占屏和对峙关系 | 必须重算动作边界、枪口、弹幕与安全区 | 采用，分阶段验证 |

试调起点为视野高 7.6、相机中心 (0.2,-0.6)、主角 X=-4.7、土豆 X=4.0、土豆可见高度 4.2。Boss 理论可见高度占比约 55%，扣除埋地后略低；这些是本项目候选参数，不是竞品实测数据。

构图对照见 [当前与目标草案](Validation/PM-008/composition_comparison.png)。左侧为已有运行截图，右侧为旧资源的离线合成，仅验证占屏和大致位置，不是已经实现的画面。草案故意只标注 HUD 安全带，不充当最终 UI 美术。

## 开发方向与范围

1. **V0.2.1，土豆体验标杆：**镜头构图、跳跃分段、翻身朝向、HUD。验收通过前不继续增加招式。
2. **V0.2.2，统一视听完成度：**标题/暂停/胜败重构，土豆嘴部与动作资源，洋葱/胡萝卜完整演出；回归现有三形态全部攻击。
3. **V0.2.3，挑战质量：**用普通玩家完整试玩校准前摇、输出窗口、反制收益和战斗时长；完善教学提示与可重复练习入口的设计。仅在前两阶段完成后实施。
4. **后续内容方向：**优先少量有明显差异的 Boss 行为、可理解的武器取舍和单关练习；暂不扩展第四 Boss、长关卡、商店、养成、联网或手柄。

当前优化目标依次为：操作连续、主体占屏、攻击可读、UI 统一、复挑战顺畅。压迫感来自体量、预备动作、节奏和反馈，不能用缩短全部前摇、提高血量或持续震屏冒充。
