## A：伤害与生命周期

1. 检查现有 IDamageable 和 TakeDamage 全部调用点。引入携带攻击编号、来源、接触点、法线和伤害值的 HitContext；统一返回 Ignored、Invulnerable、Applied、Killed 等明确结果。粉色收集使用可区分的成功结果，不能靠“没有扣血”猜测成功。旧 void 方法可短期转接，但所有碰撞入口必须走同一判定链。
2. 修改 BossProjectile、BossInsect、BossLobbedSeed、BossRootHazard，包括根须爆发重叠扫描和触发器两条路径。普通一次性弹体仅在策略允许的有效命中后消耗；无敌/闪避拒绝伤害时继续原速度和剩余寿命。持续危险区即使造成伤害也按自身寿命保留。超时、越界、被明确击破和转阶段清理分别保留独立原因。
3. L 闪避优先于接触粉色收集：闪避穿过不扣血、不奖励、不消弹。玩家独立发射的子弹仍可击破粉色弹，不能把“正在闪避”变成全局禁止其他交互。
4. 接触者停留在危险区时，无敌结束后须重新判断，使用受控 OnTriggerStay 或重叠扫描，不能只靠 Enter。按伤害冷却/攻击租期去重，避免多个 Collider 同帧重复扣血。
5. 对象池每次租用分配 generation；延迟回调和奖励携带租期并验证。先捕获接触点和反馈数据，再回收弹体，防止读取复用后的位置。回收必须幂等。

## B：反制、打击与声音

有效跳跃接触按 DESIGN-005 执行：一次性判定成功、立即计能量、星形闪光与音效、0.045 秒停顿、垂直反弹 7.5、0.18 秒反制保护、成功动作和能量飞向 HUD。满能量仍有反弹和反馈，但不能溢出；不重置二段跳次数。射击粉色弹只给较轻的击破/收集反馈。

沿用 FrameAnimator，明确普通动作、反馈动作的时间源和完成回调；不另建动画框架。视觉反冲不得移动物理根节点或枪口基准。PlayerProjectile 给 Boss 传递真实接触位置，替换 Boss 固定根部加 Y 偏移的命中特效。

建立一个时间控制入口处理手动暂停和命中停顿。命中停顿结束不能解除用户暂停；场景重试清理所有停顿令牌。战斗模拟用受控时间，短停顿时反馈/UI可继续，手动暂停时按规范冻结战斗视觉；输入边沿只缓冲一次，解除暂停不能误触攻击。普通连射命中不触发全局停顿，避免持续卡顿。

复用对象池，分别登记枪口、普通命中、粉色星环、受击、冲刺烟尘和大招特效 Prefab；不能继续把同一烟雾材质换色当作全部效果。使用 HitFeedback 上下文/事件连接视觉、镜头、音频和 HUD，各订阅者在禁用与换阶段解绑。镜头有标准、减弱、关闭选项。

音频采用可回收 AudioSource、AudioMixer 分组、事件 ID 到 AudioClip 的配置映射。落实 DESIGN-005 的 24 声部上限、优先级和事件冷却；优先保留受伤、反制和 Boss 预警，先淘汰远低优先级连射声。音乐跨阶段淡入淡出，暂停、退出、失败和重试关闭旧循环。UI 音效不受战斗暂停误伤。所有资源记录来源/许可，缺音频不得以空回调标成已实现。

## C/D：遭遇与三形态

GameManager 只组装会话服务和场景入口。新增薄 EncounterDirector（或等价现有控制器）管理 Intro、Fighting、Transition、Victory、Defeat；共用 Boss 接口暴露血量、显示名、形态标识及退场事件，各形态独立实现攻击状态，共享已有状态机与池。

BossBattleHud 从硬绑定 PotatoBoss 改为公共生命数据绑定；切换前解绑旧实例，更新名字、阶段指示和顶部中央血条。禁止继续订阅任意 boss.Died 直接 ShowVictory；仅遭遇控制器判定最后形态结束。整场进度使用设计文档公式，不能把当前形态百分比当作总进度。

新遭遇禁用旧土豆 70%/35% 的阶段调度，避免变成三乘三阶段。旧危险物模块保留，但未列入攻击表的招式不运行。过渡清除双方旧攻击体、伤害区域及异步任务，保留玩家 HP/能量，无免费治疗；重新获取控制后留至少 0.6 秒无攻击窗口。同一物理步玩家与 Boss 同死时失败优先，终态只能发布一次。

土豆按口部动作对应上中下发射点；洋葱落点预警必须先锁定、提供连续可达安全区域；胡萝卜激光最后 0.20 秒不能追瞄，追踪弹限制数量与转向率。详细时序、生命值、弹速均来自 DESIGN-005，禁止散落硬编码。阶段参数是待实测初值，不是已平衡结论。

资源放 Assets/Res 对应角色/特效/音频目录，配置保留在全局 JSON。SpriteCatalog 的硬编码 RuntimeFolders 应改为从登记的形态资源配置生成或验证，构建前检查全部引用，不能对 Assets/Res 直接 Resources.Load。每个 Boss 的所有帧统一尺寸和脚底中心，离线对齐/统一 trim；不要运行时每帧算包围盒移动 Sprite。洋葱/胡萝卜占位资源不能通过美术最终验收。

## E：界面和重试

标题页使用关卡背景与原创标题美术，接入开始、设置、退出。战斗输入只在可控阶段启用，菜单使用独立键盘焦点；载入资源和开场未结束前不接受战斗命令。设置持久化音量和镜头强度。HUD 维持左下扑克牌生命/能量、顶部中央当前 Boss 血条。

失败保持死亡一次、幽灵上升、约 2 秒后展示结算；胜利使用不同构图和节奏。结算数据使用结束瞬间快照。主要按钮重试、次要按钮返回标题，处理 Enter 双击防重复会话。重试整场，从土豆开始，重置时间、池、监听、镜头、统计、血量、能量和音频；旧会话延迟回调不得进入新会话。

## 人工验收和证据模板

每个里程碑提供版本/提交基线或工作区差异、构建路径、测试 XML、Console 日志、资源清单及录屏。用视频时间戳标出开火、普通命中、受击、反制、闪避穿弹、阶段切换和重试。录屏必须含声音；日志有 Audio 播放调用不等于听感合格。

1. 1280x720、1920x1080、窄屏窗口验证 16:9 画布、黑边、HUD、菜单焦点和文字不裁切。Boss 只埋底部且全部可见，攻击预警不被特效盖住。
2. 分别音效开/关试玩同一固定种子，再比较标准/减弱震动；记录反制确认是否明确、密集连射是否刺耳、关键预警是否可辨。
3. 测量输入响应时记录帧率、采集方法、输入事件与画面响应帧；普通录屏无法证明物理键盘到显示器的绝对延迟，必要时外部高帧率采集。不要复用离屏平均帧时间替代。
4. 至少完整打通一次三形态，并分别验证三形态死亡、暂停恢复、连续重试 10 次、回标题再开始。记录完整战斗时长、每招受击次数、反制机会和不可躲避情形；80-140 秒只作为初始调优目标。
5. 低血量、满能量、Boss 最后一滴血及同帧互杀专项复测；关闭声音仍应可凭动作/预警理解攻击，开启声音应明显增强确认。

里程碑报告分别填写“已实现 / 自动测试 / 人工画面 / 听感 / 待修复”，任何未执行项写未验证，禁止合并成一个笼统的“全部通过”。产品先验 DEV-007A/B 的反馈质量，之后再验新形态和 UI。
