# PM-006 产品版本审核与返工路线

日期：2026-09-13。负责人：产品经理。状态：审核文档已交付，游戏版本尚未通过验收。

## 1. 产品结论

当前是 V0.1 功能原型，处于体验返工阶段。已经有战斗框架和大部分功能入口，但“代码存在”不等于“操作、画面和流程已验收”。本轮检查当前工作区源码、配置、图片和历史测试记录，没有修改游戏代码、生成资源或执行 Unity PlayMode。

本轮目标是找出土豆 Boss 战中操作不连贯、反馈不明确、特效错位的原因，建立可逐项交付的修复版本。暂不增加 Boss、关卡、音效、商店或手柄支持。

《茶杯头》作为体验参照：移动响应直接，射击与位移协调，攻击有可辨识的预备、释放和收招，碰撞结果与视觉一致，死亡后能快速再挑战。当前项目保留用户指定的二段跳、L 无敌闪避、三格能量和受击后 3 秒无敌；这些是本项目规则，不当作原版默认规则。沿用仓库原创美术与内容方向，体验对标不要求照搬全部系统。本轮没有进行新的网络竞品调研。

## 4. 资源审核

### 实际盘点

| 资源 | PNG 数量 | 补间数量 | 尺寸 |
| --- | --- | --- | --- |
| Hero idle | 19 | 9 | 307×167 |
| Hero run | 19 | 9 | 307×167 |
| Hero jump | 17 | 8 | 307×167 |
| Hero dash | 15 | 7 | 307×167 |
| Hero shoot | 13 | 6 | 307×167 |
| Potato idle / attack_spit / hurt / angry | 每组 6，共 24 | 0 | 305×192 |

合计 107 张角色序列帧，其中 Hero 39 张 `_tween`。SpriteCatalog 有 108 个图片引用，包含背景；本次按 GUID 核对全部可解析，107 张角色帧均在目录中。历史记录中的“108 张序列帧加背景”需更正为“107 张序列帧加 1 张背景”。GUID 解析通过不代表 Unity 导入和发布构建已经通过。

实图抽查 `run_01_tween.png` 有明显双重人物轮廓，`idle_01_tween.png` 也存在轮廓叠影。说明已抽查的补间不是完整清晰的中间姿态；未逐帧审美验收所有 39 张补间，不能视为全部已验证。先逐帧筛选，剔除播放清单中的不合格帧，再制作真正的过渡姿态，不能用透明叠加冒充增帧。

现有尺寸一致应保留。下一轮离线处理采用整套动作对齐后计算共同包围范围、统一裁切；不能每张独立居中或独立 trim。脚底采用固定参考落地点，空中帧保持相同角色局部坐标，不把跳跃脚部逐帧强行拉到图框底边。身体中心、枪口通过固定定义或动作锚点数据标注，避免用包括尾烟的透明图框中心推断身体中心。

### Boss 与背景构图

土豆尺寸 305×192，PPU=128，scale=4.8，完整图框世界宽约 11.44、高 7.2。舞台左右界 ±7.55；Spawner 按图框半宽限制位置时，Boss 中心最大约为 1.83，无法达到配置 spawnX=5.35。这是“放大后反而向中间挤”的代码与配置原因。实际可见轮廓还受透明区和导入锚点影响，需实机核验。

策划先画舞台叠加规格：玩家左侧活动区、Boss 右侧占位、顶部血条安全区、地表线、实际受击轮廓。之后由开发同时调整尺寸与出生点，不能继续单独加 scale。前景当前复制背景底部 24%，其顶部约为 Y=-2.34，高于地面 -2.5，埋土效果还叠加 groundEmbedDepth；需要按可见土壤边缘定遮罩。

花园静态背景可以保留。本关没有地图块交互需求，继续使用背景与独立地面碰撞。震屏需验证安全裁切/超扫方案，不能让满幅背景边缘露出。

### 特效规格缺口

现有 DodgeSmoke、CombatImpact、EnergyPickup、SuperAttack 以代码构建粒子，烟雾偏软圆点，未形成期望的卡通爆烟；大招缺少与伤害对应的明确形状。部分效果每次创建 GameObject、ParticleSystem、Material，没有统一复用及材质所有权清理。

策划交付清晰轮廓的单张粒子纹理、颜色层次、作用位置、时长和排序层；烟雾仍用粒子，不恢复烟雾序列帧。开发复用已有对象池，预制效果并共享材质。建议正式资产归档：`Assets/Res/VFX/DodgeSmoke`、`HitImpact`、`PinkParry`、`SuperAttack`，各自存放 Textures、Materials、Prefabs。通用池留 Framework，效果行为留 Game/VFX，伤害判断不进入 VFX。

## 5. 必须实机核验的风险

- HealthBarView 创建 Filled Image 却未指定 Sprite；检查当前 UGUI 对无 Sprite 的绘制分支，分别截图验证 100%、50%、0% 实际宽度，不能仅断言 fillAmount。
- 落地检测缺少起跳上升过滤与充分法线约束，检查起跳后是否误判落地、错误恢复二段跳。
- 暂停时 Update 仍可读取输入，检查暂停中跳跃、开火、大招是否改动战斗状态或产生对象。
- 粒子 Shader.Find 回退及透明混合设置可能导致方块；DodgeSmoke 设置 ParticleSystem.duration 前未显式停止，需确认是否出现运行警告。
- 生命卡与固定偏移的能量 UI 在血量配置变化时可能重叠；验证不同宽高比下的 16:9 游戏区和 HUD 一致。
- 3 秒无敌、落地判断、连发密度、输入延迟和重试后的池状态需要真实碰撞及按键测试，当前阅读不能替代试玩。

## 6. 方案选择

| 方案 | 收益 | 代价与结论 |
| --- | --- | --- |
| 保留框架，先做单场土豆战的分阶段返工 | 范围可控，复用现有状态机、池和资源目录，能明确定位每项改善 | 推荐；每段验收后才进入下一段 |
| 仅提高帧率并加大粒子数量 | 改动少、短期容易看到变化 | 不能修复叠影、坐标、状态覆盖和命中失配，不作为主方案 |
| 重写角色与战斗框架 | 可以重新定义全部边界 | 回归面大，当前证据不足以支持全面重写，暂不采用 |

产品决策：优先保留用户规则；粉色弹先延续“跳跃时接触即可击碎”，不擅自改成原版需要额外时机输入的拍击。策划明确普通射击是否仍能采集的规则与提示，开发再统一两条入口。已有三阶段代码保留，但基础招式验收前不继续增加机制。

## 8. 验收清单

### 操作与动画

- [ ] 方向输入被采样后的下一次物理更新开始匀速移动；默认松手停止。记录采样、物理 tick、呈现帧，区分固定步长与渲染帧率。
- [ ] 左右移动同时射击、转身首发、跑跳连射，朝向与枪口正确，不被站立射击覆盖。
- [ ] 两次跳跃后，落地前 0.12 秒内按跳可触发落地缓冲；不凭空获得第三次跳跃。
- [ ] 连续执行二段跳 20 次，身体中心旋转且物理碰撞体不跟着翻滚；地面待机/跑动切换无锚点抖动。
- [ ] L 闪避距离与设定速度、持续时间匹配；中途反向输入不改变已开始的冲刺；边界不穿出背景。
- [ ] 抽查扩展到全部动作逐帧验收，无双影、邻帧碎片或截断；动作总时长与 gameplay 一致。

### 战斗与画面

- [ ] 受击只扣一次生命，3 秒内重复碰撞不扣血；时间到后可再次受伤，全程状态可辨识。
- [ ] 同一粉色弹被跳跃、玩家弹、重复 API 同时处理时只增加一次能量；池内已回收对象不能再次结算。
- [ ] 满三格才可释放大招；能量只扣一次；朝向、形状、有效时间与可见特效一致。
- [ ] 连续触发震屏 100 次，停止后相机回到原基准位置；背景不露边，UI 不随场景抖动。
- [ ] Boss 位于右侧，只有少量底部被土遮挡，头部不压顶部血条；子弹从已标注的发射位置出现。
- [ ] 单招预备可见，嘴部释放关键点与发弹同一时间线；上中下攻击序列至少存在可达的安全解。
- [ ] 粒子没有不透明方块或播放警告；预热后重复生成/回收 100 次，材质数和活动对象数不持续增长。

### 流程与质量

- [ ] 暂停后通过按钮和 Escape 都能恢复；暂停期间不消耗能量、不生成攻击对象。
- [ ] Boss 血条 100%、50%、0% 图形长度正确；左下生命与能量不重叠。
- [ ] 死亡动作完整播放一次，再出现幽灵上升；死亡后约 2 秒显示失败结算。
