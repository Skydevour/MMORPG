# DESIGN-006：近景对峙、连续动作与彩印花园 UI

日期：2026-09-14。依据：PM-008 用户反馈与产品审核。策划输入来自独立只读审核，由产品经理汇总确认。取代 DESIGN-005 中与本文件冲突的构图及 UI 参数；保留三形态顺序、键盘操作、扣血、三秒受击无敌、闪避不吞弹和粉色反制规则。

## 一、相机与角色构图

所有屏幕比例以实际 16:9 游戏视口计算，不包含黑边。地图世界尺寸仍为 16×9；镜头显示范围单独配置，不能缩放整个 Runtime 或 UI 根来伪装拉近。

| 候选配置 | 起点 | 调试范围/验收用途 |
| --- | --- | --- |
| camera.viewHeight | 7.6 | 7.4–8.0，对应 orthographicSize=3.8 |
| camera.centerX / centerY | 0.2 / -0.6 | 固定战斗镜头；参考视口宽约 13.51，边界 X≈[-6.56,6.96]、Y≈[-4.4,3.2] |
| level.playerSpawnX | -4.7 | 主角站位约为屏宽 14%；身体完整、脚底附近无背景台阶错觉 |
| encounter.forms[].spawnX | 4.0 | Boss 中轴约屏宽 78%；可按形态在 3.8–4.2 内调整 |
| 可见高度：土豆/洋葱/胡萝卜 | 4.2 / 4.4 / 4.6 | 未埋地轮廓约占屏高 55%/58%/61%；最终以 alpha 可见轮廓验收 |
| 可见最大宽度 | 4.8 | 检查全动作最大伸展，不仅 idle；超过时先调整资源构图而非非等比压扁 |
| embedDepth | 0.12 | 保留少量埋地，身体不能被大面积地面遮挡 |
| 场景可操作外边界候选 | X=-6.1 至 6.1 | 与视口安全边距一致；玩家实际右边界还受 Boss 左缘限制 |
| 角色/攻击可见安全边距 | 32 设计像素 | 镜头震动后仍有背景覆盖，Boss 最大轮廓不碰 HUD |

主角屏高目标约 15%–18%，不改物理尺寸。世界碰撞体、枪口和身体旋转中心不能因镜头变化发生相对偏移。土豆放大必须同时检验口部与三条弹道；身体可见尺寸、受击体和禁止穿越边界分开登记，禁止从完整透明图框直接推断全部几何关系。

离线生成各角色的可见轮廓、全动作包围、脚底、身体中心与嘴眼锚点元数据；各动作帧仍保持统一画布。Idle 参考决定可见高度，全动作包围负责出屏检查。历史资源若无法同时满足高度、宽度与发射姿态，列为美术返工，不在运行时逐帧补位置。

必须同步验证：

- 重新计算相机可见边界、出生点、Boss 前侧限制、弹体越界回收与预警位置。缩小镜头不会自动缩小旧 world bounds。
- 洋葱八列以真实可达范围划分。净安全宽度至少 1.6；两列不足时增加安全列数，不能沿用固定 `safeColumn + 1`。保守计算为 `safeSpan = ceil((1.6 + heroWidth + 2*rainRadius)/columnWidth)`，再验证实际间隙与可达时间；至少保留一个有效危险列。
- 重新检查粉色泪滴在当前站位、预警时间和跳跃轨迹下可收集；锁定后的预警不能移动。
- 首跳理论高度约 1.76，二段跳额外约 1.35，基于重力 9.81×3.2；该估算不替代长按、晚二跳、反制弹跳和旋转轮廓的真实检查。
- 暂不做随跳跃上下追踪或战斗中呼吸缩放。Boss 入场表演可使用局部动作，正常攻击不能靠持续变焦遮掩预警。

## 二、跳跃与翻身

运动状态控制物理，视觉状态按运动阶段采样。首轮保留 moveSpeed=5.5、jumpVelocity=10.5、secondJumpVelocity=9.2、重力倍率 3.2，先隔离视觉问题；需要手感调参时另记录前后轨迹。

| 视觉阶段 | 进入/退出 | 资源与时序要求 |
| --- | --- | --- |
| 起跳 takeoff | 实际新跳跃事件开始，立即向上运动 | 0.06–0.09 秒、2–3 个真实姿态；不能等待预备动画后才施加速度 |
| 上升 rise | 未接地且 vy>0.35 | 2–3 个上升姿态，根据当前状态保持或轻循环；不播放地面蹲起帧 |
| 顶点 apex | vy 在 ±0.35 内 | 1–2 个过渡姿态，最多约 0.05 秒；越过阈值立即转段 |
| 下落 fall | 未接地且 vy<-0.35 | 2–3 个下落姿态，持续到真实接地；空中不能播落地动作 |
| 落地 land | 由空中转实际接地 | 0.06–0.10 秒、2–3 个真实姿态；移动、再次跳跃和闪避可立即打断 |
| 二段翻身 air_flip | 二段跳事件触发一次 | 先保持当前 0.42 秒周期以便 A/B，再试 0.32–0.42；收身/团身/展开分明，不规定每动作九帧 |
| 反制/受击恢复 | 相应反馈结束 | 按此时 vy 和接地选择 rise/apex/fall/land，不重播起跳，不重置二段跳次数 |

旋转实现约束：物理根不旋转；镜像朝向与身体中心旋转分别负责一个视觉节点。翻身开始锁定本圈视觉朝向，水平运动与枪口方向仍可随输入即时改变，翻身末尾应用最新视觉朝向。翻身中的反制在物理上立即反弹，视觉角度用 0.04–0.08 秒最短路径回正；死亡可抢占，中断/重开必须取消旧回正任务。旋转归零点与完整圈终点等价，禁止半圈硬归零。

需要真正的新姿态资源时明确申请制作；禁止叠加两帧生成重影“补帧”，也不要恢复已被过滤的 `_tween` 当成完成。角色序列帧更新可为约 12–24 次/秒，而物理插值和旋转每个渲染帧更新。新增逐帧时长功能只有在动作关键帧需要时扩展现有 FrameAnimator，保留旧均匀 FPS 配置兼容。

## 三、Boss 压迫感

每招应能看见“预备 → 发射 → 恢复”，并与真实伤害起点一致。保持脚底稳定，允许身体局部 2%–4% 的姿态压缩，枪口/眼睛按照当前动作元数据定位。

- 土豆：吸气收紧嘴部，高/中/低对应嘴部姿态，发射短回弹，恢复放松；普通命中只局部反馈，不打断攻击时序。
- 洋葱：蓄泪、眼泪涌出与上方雨云的来源、泪雨、擦泪分清。放大后的眼睛与雨滴起点不能脱节。
- 胡萝卜：蓄光、停止追瞄、释放、眩晕有各自姿态；锁定方向的可读性优先于大面积光效。
- 普通命中不触发全局停顿；受击/反制沿用各自反馈。入场、死亡、重击可短震，标准/减弱/关闭均能读懂危险。

## 四、UI 统一基线

采用“彩印花园剧场”：有节制的墨线、植物纹样、套色和票签。花园是画面主体，纸张只用于局部菜单；标题、失败、胜利分别构图。所有以下矩形为 1280×720 左上原点 `(x,y,w,h)`，实际视口整体等比缩放，黑边不承载 HUD。

色彩：墨色 #202525、暖白 #F5F4EA、叶绿 #34785B、砖红 #BA443E、焦点黄 #F3D36A，能量粉 #E96BAD 只用于相关能量反馈。主信息对比充分，不能只凭颜色表达空满或选中。

正文使用明确授权的中文字体；标题/胜败使用独立原创题字。字号：菜单 28、正文 24、辅助 20；HUD 可按下表使用紧凑字号。字距 0，固定字号随整个画布等比缩放。菜单统一中文，保留用户要求的 YOU LOSE/胜利题字可作为画面元素。

| 界面 | 布局规格 | 反馈规格 |
| --- | --- | --- |
| HUD 顶部 | 姓名 (420,24,440,32)，血条 (380,64,520,20)，阶段紧邻姓名，三形态标记 (576,96,128,24)；去掉常驻进度百分比 | 框线 2px；新血条 0.30 秒填入；有效扣血立即反映，延迟条等待 0.12 秒后用 0.25 秒追齐 |
| HUD 左下 | 生命卡起点 (32,616)，44×64、间距 8；三格能量起点 (208,632)，36×48、间距 8 | 受损卡 0.18 秒翻灰；满能量一次 0.24 秒脉冲，倍率≤1.08；阅读状态稳定，不整组持续摆动 |
| 标题 | 题字 (96,144,480,140)，开始 (112,350,360,64)，设置/退出 Y=434/498；右侧 (720,160,460,400) 为原创三形态群像或轮廓 | 标题 0.35 秒入场、位移≤16px；开始确认后 0.25 秒淡出，立即锁重复提交；资源未就绪时禁用开始 |
| 暂停/设置 | 中央节目单 (400,112,480,496)，继续/重开/设置/标题四行中心 Y=272/336/400/464，320×56；设置替换同一区域内容 | 遮罩 alpha=0.42，进入 0.16 秒、退出 0.12 秒；焦点默认继续，关闭设置恢复原焦点，Escape 一次只处理一层 |
| 失败 | 独立破损票券 (280,154,720,390)，YOU LOSE、三节点进度；重试/标题分别 (360,430,264,64)/(656,430,264,64) | 死亡起算约 2 秒展示；题字 0.22 秒入场；按钮 0.30 秒内解锁；HUD 0.15 秒淡出；详情折叠，默认不堆六行统计 |
| 胜利 | 独立题字 (320,110,640,128)，三枚完成印章 (360,274,560,120)，摘要仅用时/受伤/粉弹收集；按钮 Y=520 | 题字 0.28 秒，印章间隔 0.08 秒，按钮≤0.45 秒可操作；少量纸屑≤24 个、≤0.8 秒；不用失败底板换文字充当胜利 |

当前统计 PinkCollected 同时包含射击采集与跳跃反制，UI 必须标“粉弹收集”；只有另增独立反制计数并验证后才可显示“反制次数”。失败进度沿用累计最大 HP 权重，节点不可均分后误导玩家。

焦点同时采用指示形状与颜色，0.10 秒切换，位移≤4px；按压 0.06 秒缩至 0.97，0.10 秒恢复，点击布局不变。装饰关闭 raycast。标题、暂停、结算不允许焦点落到不可见的底层按钮。减弱动态模式取消旋转、弹性和纸屑，保留必要淡入和状态变化。

## 五、资源与配置交付

- UI 目录：Assets/Res/UI/GardenTheatre/{Common,HUD,Title,Pause,Defeat,Victory}，分别使用 Textures/Materials/Prefabs；字体放 Fonts。
- 2×源图：生命卡 88×128，能量卡 72×96；阶段标记 64×64；标题题字 960×280、失败 1120×168、胜利 1280×256。
- 通用票签 720×128，九宫格 24px；暂停底板 960×992，九宫格 32px。胜败分别交付轮廓、题字和装饰，允许复用按钮与字体规范。
- GameConfig.json 扩展 camera、animation.hero、presentation.ui；集中屏幕 Rect、主题颜色、字体大小、动效时长。资源通过 Catalog/Prefab 序列化引用，不在 JSON 存运行时对象，不直接对 Assets/Res 使用 Resources.Load。
- 推荐边界：Framework/Animation 仅承载通用帧播放/时间采样；Game/Player 负责状态选择、运动和视觉朝向；Game/UI 分为 Hud/Menu/Results，共用主题和控件样式；GameManager 保持组装职责。迁移按一个界面逐步进行，不重写整个游戏框架。
- 所有资源登记来源、授权、动作关键点和占位状态。正式动画、题字缺失时保留明确缺口，不通过最终美术门禁。

## 六、完成标准

三种尺寸的五类界面、生命与能量所有状态、三形态最大轮廓和空中动作均需真实截图。录制长短跳、晚二跳、翻身反向、空中受击/反制、连续射击与重试；同时保存帧索引/旋转角/速度和帧时间证据。自动测试通过之外，用户应能确认主体更近、Boss 更有体量、动作不断裂、UI 风格一致。未执行项写未验证。
