# DEV-009：体验返工实施与验收

日期：2026-09-14。依据：PRODUCT_REVIEW_PM-008、GAME_DESIGNER_SPEC-006。状态：待开发。用户本轮要求产品审核和后续规格，本文不代表已经修改或测试的新版本。

共享分支同一时刻一个修改者。策划先交资源和参数清单，开发逐项接入，产品逐段验收。禁止五项全部改完后才第一次看真实画面。无资源项登记“技术待接/视觉阻塞”，不能写完成。

## A：角色动画实施

- 保留 PlayerController2D 的运动规则与 FrameAnimator 公共播放器。增加 Hero 呈现状态数据，明确当前空中阶段、跳跃序号、视觉朝向和旋转阶段；不把所有逻辑继续追加到 PlayerSpawner 的硬编码注册行。
- 空中动画由 grounded/vy/跳跃事件选择。新跳跃重置 takeoff/air_flip，普通受击/反制结束只恢复当前位置所对应的姿态。
- 空中视觉朝向与实时移动/枪口朝向解耦；优先采用独立镜像节点与中心旋转节点，保持脚底物理根和 Collider 不旋转。
- 反制立即修改物理速度与能量，视觉回正按短收束处理；手动暂停冻结战斗视觉，命中停顿沿用既有反馈时间约定，不能新增另一个全局 Time.timeScale 写入者。
- 若动作需要不同停留时长，在 FrameAnimationClip 中增加兼容旧配置的时长数据，校验长度与正值。不要用全局提高 FPS 缩短动作，也不要将起跳到落地整段无限循环。
- 缺少的 parry/hurt 等正式帧通过 Catalog 接入；离线统一裁切与锚点校验继续执行。

## B：构图与几何实施

- 将 ConfigureCamera 的 viewHeight/center 从 level.width/height 解耦；仍使用固定 16:9 视口和黑边。背景尺寸、前景遮盖和最大震动偏移检查边界覆盖。
- 由离线预处理写出 Idle 可见轮廓和全动作最大伸展元数据；Spawn 时使用这些数据一次性配置体形。全动作安全检查与身体受击体分别维护，不能拿一个透明 Sprite.bounds 同时担当两者。
- 相机、Boss 体形、出生点一起改。GameManager 继续只组装，不引入完整新场景系统；调用 EncounterDirector 的稳定角色边界绑定，保持切形态后生命/能量不变。
- 把洋葱固定两列安全逻辑改为按净宽计算 safeSpan，更新选列、粉弹、循环组数覆盖和测试。当前列内变化机制保留，不能因镜头收紧再次制造永久安全缝。
- 逐项检查土豆三路嘴部姿态、枪口世界点、胡萝卜眼睛点、泪滴顶部起点、追踪弹最小生成距离、子弹越界回收与 HUD 飞入终点。
- 先不调整全部弹速/前摇。记录改变站位后的首次来弹时间、贴近 Boss 的逃脱路径和缩小后的反制可达性，确认问题后按攻击单项调参。

## C/D：UI 实施

- 用序列化 Prefab 描述布局和资源，用薄 View 绑定玩家生命/能量、当前 Boss 和 Encounter 事件。逐屏迁移，不能保留新旧两套 EventSystem 或两份数据监听。
- Common 只共享主题、字体、按钮焦点和可取消的短动效；Hud/Menu/Results 分模块。Framework 不引用具体生命卡、Boss 或游戏统计。
- presentation.ui 集中布局、颜色、字号、反馈时长；Catalog 登记资源。替换一个界面即停用对应的运行时造图代码，避免重复 UI。
- Boss 血量立即正确，延迟条只做显示；能量飞入不重复加能量；卡牌翻灰不重复扣血；胜败内容读取冻结快照，不继续追随战斗数据。
- 结算显示时按规格收起战斗 HUD。死亡到结算约 2 秒以死亡事件起算，不能再额外叠加一段阻塞的出场动画。
- 保留并回归设置内部导航、背景点击不丢焦点、恢复原焦点、Escape 一次处理一层、重复确认防重入。关闭/重开/返回标题时取消旧动画与回调。
- “粉弹收集”和“跳跃反制”统计含义不可混淆。新增评分不是本轮范围。

## E：演出与资源

- 土豆为第一验收样板。动画表明确每一发真正的嘴部关键帧与触发点；高/中/低三发保持各自世界高度，身体放大不得让子弹从鼻子或土里出现。
- 洋葱与胡萝卜在相同基类生命周期下细分本角色演出，不能仅把 attack 数组循环得更快。补入场、预警、释放、恢复、退场资源与时序。
- 受击、反制、烟雾、危险预警分清轮廓和层级；烟雾不能遮住来弹。普通连续命中保持无全局停顿，避免回到“越开枪越卡顿”。
- 字体/题字/帧图/特效有来源登记；占位发布限制保留。没有正式资源时可提交接入接口与缺口清单，不得解除 developmentArt 门禁。

## 验收矩阵

| 编号 | 操作/条件 | 必须观察的结果 |
| --- | --- | --- |
| A01 | 长按、短按首跳；第一次顶点前后进行二段跳 | takeoff 一次；落地帧仅实际接地出现；运动不等待动画 |
| A02 | 翻身 0.1/0.2/0.3 秒时反向，持续射击 | 身体旋转连续；水平响应和枪口朝向正确；Collider 中心不绕圈 |
| A03 | 翻身四分之一圈/半圈受击、反制、闪避 | 不硬回放地面起跳；反制立即反弹，视觉短收束；无奖励重复 |
| A04 | 落地瞬间再次跳跃、方向反转、闪避 | 保留已有缓冲/宽限规则；落地表现可被打断，不额外锁操作 |
| B01 | 三尺寸、三 Boss 所有姿态、最大空中高度 | 全动作轮廓在视口安全区；背景不露边，枪口/眼睛/碰撞体一致 |
| B02 | 洋葱边缘和各列边界连续六轮；从旧安全区移动 | 无永久安全缝，净安全宽度≥1.6，预警冻结且玩家按正常速度可达 |
| B03 | 土豆三路、激光早/准/晚闪、两追踪弹、粉弹反制 | 变化后的镜头与站位仍有安全解；闪避不消弹，反制不重置二段跳 |
| C01 | HP 3/2/1/0、能量 0/1/2/3、Boss 100%/50%/0% | 空满/损失/当前状态清楚；数据即时正确，装饰不改变数据 |
| D01 | 标题/设置/暂停/胜败，键盘和鼠标各走一轮 | 焦点可见且不逃逸，点击背景可继续键盘操作，重复确认只执行一次 |
| D02 | 翻牌/血条追齐/结算入场期间重开或回标题十次 | 无旧动画、声音、HUD 监听、弹体、相机偏移进入新会话 |
| E01 | 有声与静音、标准/减弱/关闭震动完整挑战 | 不靠声音或震屏独占关键信息；演出和伤害事件吻合 |
| P01 | 真正前台运行，记录硬件/分辨率/同步方式与输入 | 目标稳定 60 FPS；区分 CPU/GPU 帧耗时、姿态帧率和输入至呈现帧，不用离屏平均值代替 |

30/60/120 FPS 目标验证要记录实际达到的帧率；精准时间单元测试可使用固定模拟步长，但不能拿它证明前台手感。输入延迟用队列事件到物理/视觉响应的帧记录，物理键盘到屏幕的绝对延迟未测就写未测。
