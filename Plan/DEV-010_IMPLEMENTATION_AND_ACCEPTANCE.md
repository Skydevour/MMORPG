# DEV-010 分阶段实施与验收

依据PM-009及DESIGN-007。当前为待开发规格，本轮未修改代码或制作正式资源。

## 实施顺序

1. 资源审定：三Boss同屏样张、土豆入场/三路吐弹关键姿态、HUD/失败稿、声音样段。没有匹配嘴型时不先用坐标偏移假装同步。
2. 土豆样板：统一攻击时间轴、逐帧锚点、专属钻土入场与土沿遮挡，接入命中/反制/受伤的完整视觉声音事件。
3. UI实现：保留Catalog/Prefab及View职责，替换资源和布局，回归键鼠焦点、暂停、重试；不另造第二套菜单框架。
4. 扩展洋葱天降及胡萝卜四周显形，使用统一生命周期和各自演出资产；落实阶段音乐衔接。
5. 全量回归、三尺寸前台有声录像、人工体验验收，再构建新试玩包。旧包按用户清理要求在新包验证后清理。

## 开发结构

- Framework/Animation负责通用播放与时间推进；提供可枚举区间内标记的能力，含越帧、循环/非循环和取消语义，不引用Boss、音频或子弹类型。
- Game/Bosses负责AttackSequence与每位Boss事件绑定。逻辑与画面消费同一个序列时钟和事件ID；暂停、顿帧、死亡、重试不能漏发/补发/重复发。不要让SpriteRenderer是否可见决定逻辑命中。
- 先替换PotatoBossController的AttackVisualProgress和独立attackShotTimer时序，再移除已废弃路径。普通机器帧跨越release标记也恰好发一次；极端卡帧时不无限补发造成瞬时弹墙，制定有界推进策略并记录中文诊断。
- 标记字段候选：clip、frameDuration、markers(time,eventId,shotIndex,muzzle)、recoverEnd。静态数值集中GameConfig；Sprite及Prefab引用在Catalog，离线标定数据在Data，不把路径散在Update。
- EncounterDirector只管理Title/Intro/Fighting/Transition/Result和战斗锁。每Boss的Enter/Exit播放器返回完成或取消信号，替换0.45/0.6硬编码和统一根节点scale。视觉节点与受击框分开；入场碰撞/伤害开关明确，结束时恢复一次。
- 子弹、接触闪光和吐气声由同一release事件派发；Hit/Parry/Hurt/Super用独立反馈配置，复用现有对象池和BattleAudio，拆事件资源不重复造池。
- 导入阶段校验统一尺寸、脚底锚点、嘴位、缺帧和事件次数。正式资源不允许缺失时静默生成公式占位图；开发回退显式标记。
- GardenAssetPreparation目前会重新写入部分菱形特效贴图；正式导入与占位生成必须分离。资源准备重复运行后校验正式资产哈希/GUID不变，防止新美术被旧生成器覆盖。

## 验收

| 类别 | 验证方式与通过条件 |
| --- | --- |
| 同步 | 30/60/120目标帧率录制三轮吐弹，逐发开嘴、子弹和口部效果在同一渲染帧，口部偏差候选不超过1280基准下6像素；声音起音延迟实测，不能仅验证调用顺序 |
| 事件 | 一轮恰好3发，暂停/死亡/重试/跳帧边界无多发、漏发或上轮残留；加入接近release时取消的测试 |
| 入场 | 土豆先隐藏于土下再爬出，洋葱从上方落下，胡萝卜四周效果到右侧唯一实体；无根节点纵向拉伸替代，未完成不攻击，不提前丢失画幅/碰撞边界 |
| 反馈 | 普通连射操作连续；反制视觉、能量、弹体回收、反弹各一次；受伤3秒无敌；闪避不吞弹；每类事件声音可辨 |
| UI | 三尺寸美术截图人工验收，标题/设置/暂停/胜败键鼠完整走通，动画中十次重试或返回无残留 |
| 混音 | 耳机及扬声器听检；60秒连续射击不疲劳，反制/受伤/预警可辨，无削波/循环爆点；暂停/重试无旧声音循环 |
| 性能 | 前台真实战斗测CPU/GPU、粒子峰值及帧时间；画面覆盖用的关闭AI脚本不得冒充压力或真人手感测试 |
